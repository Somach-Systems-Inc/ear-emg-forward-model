    points under a 0.1% mesh perturbation, so MAG here is dominated by how the
    15 mm disc electrodes get meshed onto the surface rather than by volume

    commit, that a depth-flat MAG offset points at the electrode model, and it
    promotes it from suspicion to measurement.

      - no discretisation term can be extracted at this precision until the
        electrode confound is removed
      - the earlier +4.4% MAG must NOT be quoted as an accuracy figure, since a
        nominally identical mesh gives +9.5%

    RDM/MAG replace the ratio; item 3 is not answerable on a concentric sphere
    
    ITEM 2 DONE. RDM and MAG over all 120 sources, no conditioning restriction and
    no exclusion criterion in the headline:
    
        RDM  median 4.355 %   mean 5.669   90th pct 11.406   max 19.921
        MAG  median +4.400 %  mean +4.676  10-90 pct -1.05 to +10.57
    
    Definitions per Meijs et al. 1989 as used throughout the EEG forward
    literature: RDM = 50*||u_num/|u_num| - u_ana/|u_ana||| bounded 0-100,
    MAG = 100*(|u_num|/|u_ana| - 1) unbounded above. Both need the full electrode
    topography, so the harness now builds a real lead field matrix -- 16 electrodes
    each solved reciprocally against a common reference -- rather than the single
    bipolar pair, for which RDM degenerates to a sign.
    
    The polarity convention is applied once from the aggregate sign, never per
    sample.
    
    ITEM 3 IS BLOCKED BY A CONFOUND, and the measurement is what exposed it. RDM
    FALLS as sources approach the interface: 2.54% at 0-5 mm against 8.96% at
    40-100 mm, correlation with interface distance +0.676. Read naively that says a
    conductivity jump improves accuracy, which is not plausible.
    
    The cause is that on a concentric sphere a source at radius r sits at distance
    (78 - r) mm from the innermost interface BY CONSTRUCTION. Distance-to-interface
    and eccentricity are perfectly collinear, and no regression can separate them.
    What the numbers actually show is the well-known degradation of EEG forward
    solutions for deep central sources, whose topographies are low-amplitude and
    poorly conditioned.
    
    So row 2 of the error budget is marked "needs a different geometry" rather than
    filled with a number that would be measuring eccentricity and labelled
    interface proximity. Getting it honestly requires a geometry where two sources
    at equal eccentricity sit at different interface distances: a sphere with an
    eccentric inclusion, or the head mesh with the oracle replaced by a converged
    fine-mesh reference. Recorded as a designed experiment, not dropped.
    
    This also disposes of the r=40 mm anomaly Carl flagged. It was NOT interface
    proximity: 40 mm is 38 mm from the nearest boundary, the second-farthest
    sampled. MAG is flat across radii (+3.6 to +5.2%), so the old 1.033 was
    conditioning noise in a metric now retired.
    
    NOTE FOR ITEM 1: MAG median +4.4% is much larger than the 0.7% the bipolar
    ratio suggested, and flat with depth. Flat-with-depth points at the electrode
    model rather than the solver -- the analytic sphere assumes point electrodes
    while SimNIBS models 15 mm discs with 2 mm thickness. The convergence study now

    Stage 1: label inventory + mesh build, with hard failure on unresolved labels
    
    01_build_mesh.py has two modes.
    
    --list-labels <nifti> inventories every label integer (voxel count, physical
    volume, anatomical name), writes results/01_label_inventory.csv, and ends with
    an explicit verdict on the CLAUDE.md fork: are digastric / stylohyoid /
    mylohyoid / geniohyoid / genioglossus individually segmented, or pooled into a
    generic muscle catch-all? It reports FOUND/MISSING per muscle and names any
    catch-all label they were likely absorbed into. It imports only numpy and
    nibabel, so the label question can be resolved before SimNIBS is installed --
    that fork decides the paper's design and should not be blocked on a 4 GB
    install.
    
    Lookup tables are auto-discovered next to the volume and scored by label
    overlap; --lut overrides. Parses FreeSurfer/ITK-SNAP, csv/tsv, plain and json
    formats. With no LUT resolved the script reports NOT RESOLVED rather than
    guessing names.
    
    Default mode runs SimNIBS meshmesh and writes data/mida_headneck.msh. It
    refuses to run while any config.MUSCLES entry still has mida_label = None --
    per CLAUDE.md, a wrong label is worse than a missing one.
    
    Conductivities are emitted to results/01_conductivity_map.csv rather than
    baked into the mesh, because a SimNIBS .msh carries tissue TAGS, not
    conductivities; the values bind at simulation time in stage 3 via
    s.cond[label-1].value. That file is the source for Table 1. Flagging this
    because the stage-1 spec said "assign per-label conductivities" and this is
    the honest reading of it, not a silent reinterpretation.
    
    Every precondition failure prints what is missing and what to do, and exits
    non-zero: absent label volume (with MIDA's registration URL), non-integer
    volume mistaken for a label map, meshmesh not on PATH, existing mesh without
    --force. No path is ever guessed.
    
    requirements.txt pins the stack and documents the Python 3.11 constraint: the
    only native Apple Silicon SimNIBS 4.6.0 build is a cp311 wheel, so a 3.12+
    interpreter cannot load it. README records both install routes and the
    Apple Silicon PARDISO/MUMPS solver constraint that will bite at stage 3.
    
    Verified against synthetic label volumes covering both fork outcomes,
    LUT auto-discovery, and all four failure paths. Not yet run against MIDA.
